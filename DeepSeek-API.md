# DeepSeek API Architecture

## Current Worker Surface

The Worker currently exposes only three HTTP surfaces:

| Method | Endpoint | Responsibility |
|---|---|---|
| `POST/GET/DELETE` | `/auth` | Credential control-plane: store, inspect sanitized status, or clear credentials in KV |
| `POST` | `/deepseekprotocol` | Direct DeepSeek protocol operation; returns the raw DeepSeek SSE stream |
| `GET` | `/health` | Basic Worker health/authentication status |

The legacy OpenAI-compatible `/v1/chat/completions` route, OpenAI response translation, and Worker-side protocol SSE translation are removed from the current Worker.

## Layer Ownership

```text
Worker
├── /auth
│   └── credentials → KV
│
├── /deepseekprotocol
│   └── deepseek_api
│       ├── DeepSeek wire protocol
│       ├── credentials / HIF-LEIM via ProtocolStateStore
│       ├── session state via ProtocolSessionStore
│       ├── session creation and validation
│       ├── parent_message_id resolution
│       ├── request construction
│       ├── PoW / HIF-LEIM / headers
│       └── protocol SSE parsing
│
└── /health
```

`deepseek_api` owns DeepSeek protocol semantics. Cloudflare-specific persistence remains in adapters:

```text
ProtocolStateStore
    └── CloudflareKVStateStore

ProtocolSessionStore
    └── CloudflareD1ProtocolSessionStore
```

## `/deepseekprotocol` Input

`POST /deepseekprotocol` accepts the protocol-facing request below.

```json
{
  "session": {
    "chat_session_id": "string"
  },
  "prompt": "string",
  "model_type": "string|null",
  "thinking_enabled": false,
  "search_enabled": false
}
```

### Validation

- `prompt` is required and must be a non-empty string.
- `model_type` is required and may be `null` or a string.
- `thinking_enabled` is required and must be boolean.
- `search_enabled` is required and must be boolean.
- `session` is optional.
- When `session` is supplied, only `session.chat_session_id` is accepted from the caller.
- The caller does **not** supply an authoritative `parent_message_id`.
- `ref_file_ids`, `action`, and `preempt` are not caller-controlled fields.

The endpoint returns the raw DeepSeek SSE response as `text/event-stream`.

## Session State Ownership

Session lifecycle belongs to `deepseek_api`.

### New session

```text
POST /deepseekprotocol without session
        ↓
deepseek_api.createSession()
        ↓
POST /api/v0/chat_session/create
        ↓
D1 session created with parent_message_id = NULL
        ↓
completion uses parent_message_id = NULL
```

### Existing session

```text
POST /deepseekprotocol with chat_session_id
        ↓
deepseek_api reads ProtocolSessionStore
        ↓
missing session → 404
        ↓
stored parent_message_id becomes authoritative
        ↓
DeepSeek completion request
```

The caller cannot override the D1 `parent_message_id`.

### Advancing the session

The completion SSE `ready` event contains the authoritative `response_message_id`.

```text
ready.response_message_id
        ↓
Protocol SSE parser
        ↓
ProtocolSessionStore.advance()
        ↓
D1 parent_message_id becomes response_message_id
```

The SSE stream itself is passed through unchanged to the caller.

## D1 Session Schema

The canonical table is:

```sql
CREATE TABLE sessions (
  chat_session_id TEXT PRIMARY KEY,
  parent_message_id INTEGER,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
```

`parent_message_id` is nullable because a newly-created DeepSeek session has no parent message yet.

The schema transition from the old `NOT NULL`/`0` representation is performed by the Wrangler D1 migration:

```text
migrations/0001_protocol_sessions.sql
```

The migration is transactional and converts the legacy `parent_message_id = 0` first-turn sentinel to `NULL`.

Runtime requests do not perform destructive schema migrations.

### ProtocolSessionStore

The protocol abstraction exposes:

```text
initialize()
get(chat_session_id)
create(chat_session_id)
advance(chat_session_id, parent_message_id)
```

The implementation in `src/adapters/cloudflare-d1-protocol-session-store.ts` contains the Cloudflare D1 SQL.

## Protocol State in KV

`ProtocolStateStore` remains the platform-independent abstraction for protocol KV state.

Canonical keys:

```text
PROTOCOL_STATE_KEYS.AUTH
PROTOCOL_STATE_KEYS.HIF_LEIM
```

- `AUTH` stores the personal Worker credentials used by `deepseek_api`.
- `HIF_LEIM` stores the cached HIF-LEIM value.

## Fixed DeepSeek Wire Fields

The following fields are protocol constants and are always generated by `deepseek_api`:

```json
{
  "ref_file_ids": [],
  "action": null,
  "preempt": false
}
```

They are not supplied by the Worker caller.

## Complete DeepSeek Wire Request

The request sent to the external DeepSeek completion endpoint is:

```json
{
  "chat_session_id": "string",
  "parent_message_id": "number|null",
  "model_type": "null|string",
  "prompt": "string",
  "ref_file_ids": [],
  "thinking_enabled": false,
  "search_enabled": false,
  "action": null,
  "preempt": false
}
```

`parent_message_id` comes exclusively from protocol session state:

- `null` for the first turn of a newly-created session.
- The stored D1 value for subsequent turns.

## Internal DeepSeek Wire Endpoints

These external DeepSeek endpoints are called internally by `deepseek_api` and are not exposed by the Worker as public routes.

| Endpoint | Purpose |
|---|---|
| `POST https://chat.deepseek.com/api/v0/chat_session/create` | Create a DeepSeek chat session |
| `POST https://chat.deepseek.com/api/v0/chat/create_pow_challenge` | Acquire the completion PoW challenge |
| `GET https://hif-leim.deepseek.com/query` | Acquire HIF-LEIM |
| `POST https://chat.deepseek.com/api/v0/chat/completion` | Send the DeepSeek completion and receive SSE |

## Internal Completion Flow

```text
1. Resolve credentials from ProtocolStateStore
2. Resolve/create DeepSeek chat session
3. Resolve authoritative parent_message_id from ProtocolSessionStore
4. Build exact completion request
5. Acquire HIF-LEIM (cached)
6. Request PoW challenge
7. Solve PoW
8. Build DeepSeek completion headers
9. POST /api/v0/chat/completion
10. Pass raw SSE through the Worker
11. Parse ready.response_message_id from the stream
12. Advance D1 session state
```

## Session Lifetime

The DeepSeek wire contract reports a session TTL of `259200` seconds (3 days). The Worker stores the protocol continuation state in D1 using `chat_session_id` as the primary key.

HIF-LEIM is cached in KV and refreshed according to its protocol cache policy.

## Completion SSE Protocol

### `ready`

```text
event: ready
data: {"request_message_id":1,"response_message_id":2,"model_type":"default"}
```

`response_message_id` becomes the next `parent_message_id`.

### `update_session`

```text
event: update_session
data: {"updated_at":1789181711.2138479}
```

### `data`

Content updates are delivered as DeepSeek protocol patches, for example:

```text
data: {"p":"response/fragments/-1/content","o":"APPEND","v":"Hello"}
```

### `title`

```text
event: title
data: {"content":"Auto session test"}
```

### `close`

```text
event: close
data: {"click_behavior":"none","auto_resume":false}
```

The Worker does not translate these events to OpenAI-compatible events.

## Model Type

The completion wire field is `model_type`.

Known protocol values include:

| Wire Value | Meaning |
|---|---|
| `null` | Default model path |
| `"expert"` | Expert model path |

The Worker does not perform OpenAI model-name mapping. Any higher-level model mapping belongs to a future translator/adapter layer.

## Future Translator Layer

An OpenAI-compatible translator can be added later without changing `deepseek_api`.

Its responsibility would be limited to:

```text
OpenAI/OpenCode request
        ↓
translator
        ↓
DeepSeek protocol request
        ↓
deepseek_api
        ↓
raw DeepSeek SSE
        ↓
translator
        ↓
OpenAI/OpenCode response
```

The translator must not own DeepSeek credentials, PoW, HIF-LEIM, session semantics, or `parent_message_id` state.
